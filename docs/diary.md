# Дневник

Документация модуля: личный дневник и дневник девушки солдата (письма).

## Что использовано

Проект на **Expo SDK 51**. Документация API: https://docs.expo.dev/versions/v51.0.0/

| Задача | API / библиотека |
| --- | --- |
| Хранение записей и тем | `expo-sqlite` 14 (`openDatabaseAsync`, `execAsync`, `runAsync`, `getFirstAsync`, `getAllAsync`) |
| Фото | `expo-image-picker` 15 (`launchImageLibraryAsync`, `launchCameraAsync`) |
| Копирование фото в песочницу | `expo-file-system` 17 (`documentDirectory`, `copyAsync`) |
| UUID | `expo-crypto` (`randomUUID`) |
| Жесты переноса/ресайза фото | `react-native-gesture-handler` 2 + `react-native-reanimated` 3 |
| Цветовой круг | `react-native-svg` (секторы HSV) + pan/tap |
| Дата письма | `@react-native-community/datetimepicker` (`DiaryDateButton`) |
| Книга писем PDF | `expo-print` 13 (`printToFileAsync`) + `expo-sharing` |
| Даты службы в настройках | общий `DatePicker` (системный календарь Android) |
| Навигация | React Navigation 6, stack внутри вкладки «Дневник» |
| Код дневника | `expo-secure-store` 13 + `expo-crypto` (SHA-256) |
| Биометрия | `expo-local-authentication` 14 |

Код и биометрия закрывают только личный дневник.

## Архитектура

Два продукта на **одном редакторе**. Различия только в обвязке (тема дня, рандом, подтверждение смены темы).

```
Вкладка Diary
 └─ DiaryStackNavigator
     ├─ DiaryHome          две кнопки дневников; карточка «Книга писем» скрыта флагом
     ├─ PersonalDiary      сразу лист на выбранную/сегодняшнюю дату
     ├─ LetterTheme        «Твоя тема на сегодня» + набор текста 32 с
     └─ LetterEditor       тот же DiaryEditor + shuffle
```

Общий лист: `src/components/diary/DiaryEditor.tsx`.

### Модель документа

Не WYSIWYG-WebView и не один большой HTML. Документ — массив блоков:

- `paragraph` — массив span’ов `{ text, style }` (размер, цвет, bold/italic/underline, шрифт)
- `image` — `uri`, `widthRatio` (доля ширины рабочей области), `aspectRatio`

Так фото вставляется «в абзац», его можно переставлять между блоками и масштабировать, не борясь с `contenteditable`.

Форматирование:

- каретка без выделения → меняется стиль печати (`typingStyle`), уже набранный текст не трогается
- есть выделение → стиль применяется к диапазону (`applyStyleToRange`)
- размер шрифта выбирается выпадающим списком в тулбаре (`14 / 16 / 18 / 22 / 28`)
- текст использует основной шрифт приложения (`dmb-timer-sans`, жирный — `dmb-timer-sans-Bold`); выбор семейства временно скрыт

Цвет: плавный круг HSV (угол = тон, радиус = насыщенность), полоса яркости с непрерывным жестом и маркером, поле HEX. Полоса — градиент от чёрного до самого светлого выбранного оттенка. Во время жеста маркеры двигаются на UI-потоке; цвет документа обновляется один раз при отпускании, чтобы не перерисовывать редактор и SVG на каждый пиксель.

### Фото

Кнопка «+» справа снизу. Вставка:

- фокус на пустом абзаце → фото становится на его место, после него остаётся пустой абзац для текста
- фокус на абзаце с текстом → фото со **следующего** абзаца (как просили)
- нет фокуса → после последнего блока

Тап по фото показывает ручки:

- слева сверху — удалить
- по центру — перенос (pan, перестановка блока по Y)
- справа снизу — размер (равномерное растяжение)

Во время изменения размера ширина и высота обновляются на UI-потоке Reanimated. React-документ получает итоговый `widthRatio` один раз после отпускания ручки, поэтому редактор не перерисовывается на каждом пикселе жеста.

Ограничения размера:

- минимум **1/6** ширины/высоты рабочей области (лист)
- максимум — не больше листа

Файлы копируются в `documentDirectory/diary/`.

### База данных

Отдельные таблицы, не JSON в `config` (темы должны жить в БД):

```sql
letter_themes (id, title, sort_order)
diary_entries (id, kind, entry_date, theme_id, content_json, updated_at)
UNIQUE(kind, entry_date)
```

Сиды тем — каталог в `src/data/letterThemes.ts` и список в `docs/letter-themes.md` (около 800 тем). Тон: простой и приземлённый, без литературности и без слишком узких хобби. Не привязываем тему к текущему месяцу. При смене `LETTER_THEMES_SEED_VERSION` перезаписываются только сиды; темы с id `custom-*` остаются. Первые три темы сохранены:

1. Наша первая встреча
2. Наше первое свидание
3. Наш первый поцелуй

`kind`: `personal` | `letter`. Одна запись на дату внутри каждого вида. Прошлые дни редактируются через календарь в шапке (`DiaryDateButton`, будущие даты закрыты). На Android дата применяется только при `event.type === 'set'`.

`resetAllData` чистит `diary_entries`, каталог тем оставляет.

Использованная тема = `theme_id` у сохранённых писем. Повторно не выдаётся. Для перевыбора темы текущего дня эта дата исключается из «занятых», чтобы можно было оставить ту же тему при рестарте анимации, но чужие занятые темы не предлагаются.

Если на дату письма попадает праздник (вкладка «События», см. `docs/events.md`), первой выдаётся виртуальная тема `Как я отмечала {название} {год}`. Каталог в этот день остаётся доступен через shuffle и поиск.

## Потоки экранов

### Личный дневник

Главная вкладки → «Личный дневник» → сразу страница **сегодня** в режиме чтения. Календарь в шапке, иконка карандаша. Редактирование: «Сохранить» и крестик (с подтверждением). «+» для фото только в режиме правки. Уход назад с несохранённым — диалог сохранить / не сохранять / отмена.

### Письма

Если на сегодня уже есть сохранённое письмо → сразу редактор.

Иначе экран темы:

- заголовок «Твоя тема на сегодня:»
- если день совпал с праздником – сначала тема «Как я отмечала {название} {год}» (см. `docs/events.md`)
- тема сразу целиком тем же `AnimatedText`, что в онбординге: **1 секунда** паузы, затем проявление с подъёмом за **2 секунды**
- через **1 секунду** появляется «Я готова» (ждать проявление не обязательно)
- лупа справа сверху открывает поиск по всему каталогу (задержка 350 мс) и добавление своей темы
- своя тема пишется в `letter_themes` с id `custom-{uuid}` и сразу выбирается
- уже использованные темы в поиске видны, но выбрать их нельзя
- shuffle рядом перезапускает экран и берёт другую свободную тему
- «Я готова» → редактор с чистого листа и выбранной темой

В редакторе писем всё как в личном, плюс shuffle в шапке:

> Точно поменять? Ваши изменения не сохранятся.

Подтверждение уводит на экран темы без записи в БД.

Если свободных тем нет — можно найти тему в поиске или добавить свою.

## Книга писем (PDF)

Письма солдату можно собрать в книгу. Входят только непустые письма (`kind = letter`) по дате. Личный дневник в PDF не попадает, но его количество есть в статистике.

Точки входа:

- хаб дневника → карточка «Книга писем» (сейчас скрыта, `SHOW_LETTER_BOOK_HOME_ENTRY`);
- итоги на дембель → «Собрать книгу писем».

Три макета, одна и та же статистика, что в итогах (срок службы, звонки, встречи, дневник):

| Макет | Характер | Как устроена книга |
| --- | --- | --- |
| **Том писем** | классика, кремовая бумага, serif | титул, содержание, каждое письмо с новой страницы, послесловие с итогами |
| **Календарь ожидания** | дневник по месяцам | сначала сводка ожидания, затем письма с датой слева, группы «сентябрь 2026» |
| **Мы ждали** | тёмный альбом | огромное число дней, карточки итогов, письма как открытки с рамкой у фото |

Сборка: HTML → `Print.printToFileAsync` (страница A5, 420×595 pt).

Фото:

- по умолчанию **добавляются**;
- галочка «Добавлять фото» / «Игнорировать фото»;
- в книге всегда **по центру**, ширина **68%** полосы, пропорции как у снимка;
- в PDF вкладываются base64 (на iOS локальные `file://` не печатаются).

Форматирование письма сохраняется у каждого span: цвет, размер (14–28), жирный, курсив, подчёркивание. Макет книги задаёт только бумагу и заголовки, не перекрашивает текст.

Пустые письма пропускаются. После сборки: «Поделиться» или «Печать».

Если писем ещё нет или нет нативного `ExpoPrint` — ошибка, без файла.

Файлы: `src/types/letterBook.ts`, `src/utils/letterBookHtml.ts`, `src/utils/exportLetterBook.ts`, `src/components/diary/LetterBookExportModal.tsx`.

## Решения, которые сознательно приняты

1. **Блоки, а не WebView.** Нативный стек, те же жесты, что в трекерах, без новой зависимости. Курсор = фокус абзаца + selection в `TextInput`.
2. **Режим чтения по умолчанию.** Карандаш открывает правку; крестик спрашивает подтверждение и откатывает документ к последнему сохранению. Сохранение возвращает в чтение.
3. **Явное сохранение**, без автосейва. Совпадает с требованием кнопки сохранения; случайный уход не перетирает день.
4. **Перенос фото = порядок блоков**, не абсолютный холст. Иначе «вставка в абзац» и свободный drag конфликтуют. Ресайз ограничен рамкой листа.
5. **Темы в SQLite, тело записи — JSON блоков.** Темы выбираются SQL’ом, верстка листа версионируется (`document.version = 1`) и может эволюционировать без миграции столбцов.
6. **Нижняя вкладка скрывается** на теме и в редакторе, чтобы лист был рабочей областью.

## Настройки и защита личного дневника

Шестерёнка справа сверху на хабе дневника → `SettingsScreen`.

| Блок | Что делает |
| --- | --- |
| Имена | `user_name` / `partner_name` в `config`. Имя любимого — заголовок основного таймера на главной |
| Даты службы | призыв / дембель, `DatePicker`, те же кнопки 365 / 547 дней, что в онбординге |
| Код | 4 цифры, SHA-256 + соль в `expo-secure-store` |
| Биометрия | `expo-local-authentication`, только если код уже задан |
| Данные для проверки | переключатель основной / тестовой SQLite |

Личный дневник при включённом коде открывается через `DiaryLockScreen`: клавиатура как на экране разблокировки телефона (цифры `dmb-timer-sans-Bold`), слева внизу — лицо и/или отпечаток, если биометрия включена и есть на устройстве. Сначала системный запрос биометрии, иначе код. Код дневника свой, не код телефона. Письма кодом не закрываются. Вкладка «Настройки» скрывает нижнюю панель. При включении кода биометрия включается сама, если на телефоне уже есть лицо или отпечаток.

### Две базы

Активный профиль лежит **вне** SQLite, в `documentDirectory/database-profile.json`. Поэтому переключение не пишет в боевые данные.

| Профиль | Файл | Что внутри |
| --- | --- | --- |
| `main` | `zhdi.db` | настоящие письма и настройки; сидом не заполняется |
| `sandbox` | `zhdi-sandbox.db` | отдельная копия схемы; при первом входе — 365 писем, личный дневник через день, звонки и встречи |

Тестовая база: призыв = сегодня минус 365 дней, дембель = сегодня (фаза `after`, можно сразу смотреть итоги и книгу). Письма с разным цветом/кеглем, каждое пятое с картинкой-заглушкой. Версия сида — `config.sandbox_seed_version`. Кнопка «Заполнить тестовую заново» переписывает только sandbox.

На главной и в хабе дневника видна красная полоска «Тестовая база». После переключения приложение пересобирает навигацию (`reloadAppSession`), основная база на диске остаётся как была.

Файлы: `src/services/database/profile.ts`, `sandboxSeed.ts`, `src/appSession.ts`.

Файлы настроек: `src/screens/diary/SettingsScreen.tsx`, `DiaryLockScreen.tsx`, `src/services/diaryLock.ts`, `src/hooks/useProfile.ts`.
