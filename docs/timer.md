# Таймер службы

Документация главного экрана: круговой и линейный таймер, плашки «Прошло / Осталось», настройки вида и фото на фоне.

## Что использовано

Проект на **Expo SDK 51**. Документация API: https://docs.expo.dev/versions/v51.0.0/

| Задача | API / библиотека |
| --- | --- |
| Настройки и даты службы | `config` в `expo-sqlite` |
| Фото на фоне | `expo-image-picker` 15 (`launchImageLibraryAsync`) |
| Копирование фото в песочницу | `expo-file-system` 17 (`documentDirectory`, `copyAsync`, `deleteAsync`) |
| Ползунок затемнения | `react-native-gesture-handler` 2 + `react-native-reanimated` 3 |
| Кольцо / сегменты | `react-native-svg` |
| Расчёт прогресса | `date-fns` (`startOfDay`, `differenceInCalendarDays`) |
| Склонение подписей | `src/utils/inflection.ts` |
| Навигация | React Navigation 6, stack внутри вкладки «Главная» |
| Дата | `@react-native-community/datetimepicker`, спиннер `DatePicker` |
| Картинка таймера | `react-native-view-shot` 3.8 (`captureRef`, PNG) |
| Сохранить в галерею | `expo-media-library` 16 (`saveToLibraryAsync`, write-only) |
| Поделиться файлом | `expo-sharing` (`shareAsync`, PNG) |
| Виджет Android | `react-native-android-widget` 0.13 |

Сборка — development client или релиз (`expo-dev-client`). Нативные модули проверяются в `src/utils/nativeAvailability.ts`: если модуля нет, экран таймера всё равно открывается, а снимок, галерея, виджет и праздничные пуши просто не вызываются.

## Фазы таймера

`resolveTimerPhase` сравнивает сегодня с полуночью начала и конца.

| Фаза | Когда | График | Центр | Плашки |
| --- | --- | --- | --- | --- |
| `before` | сегодня **до** дня начала | 0% | дни до старта | одна: «ДО ПРИЗЫВА» / «ДО НАЧАЛА» |
| `active` | от дня начала **до** дня конца (день конца уже не active) | обычный прогресс | ддд / дпп | две: «ПРОШЛО» и «ОСТАЛОСЬ» |
| `after` | день конца и дальше | 100% | дни после конца | одна: «ПОСЛЕ ДЕМБЕЛЯ» / «ПОСЛЕ» |

Призыв в будущем в онбординге разрешён. Дембель должен быть строго позже призыва.

## Итоги после дембеля

С полуночи дня дембеля (фаза `after` основного таймера службы, не своих таймеров) на главном экране появляется кнопка **«Итоги»**. Она не входит в картинку для шаринга и не зависит от глаза, который прячет плашки «Прошло / Осталось».

Нажатие открывает шторку `ServiceSummaryModal` со статистикой ожидания:

| Блок | Что показывает |
| --- | --- |
| Шапка | имя солдата, число дней службы, даты призыва и дембеля |
| Звонки | те же карточки, что на вкладке трекеров |
| Встречи | те же карточки, что на вкладке трекеров |
| Дневник | сколько личных записей и писем |

### Автопоказ в день дембеля

В календарный день дембеля шторка открывается сама, без нажатия:

1. первый заход в приложение за этот день (холодный старт или возврат из фона);
2. если приложение уже открыто в 23:59 преддембельского дня — в 00:00 того же перехода.

Повторно за тот же день сама не открывается: в `config` пишется ключ `service_summary_auto_shown_date` (`yyyy-MM-dd`). Кнопка «Итоги» после этого остаётся, статистику можно открыть вручную. В дни после дембеля автопоказа нет, только кнопка.

В шторке итогов есть «Собрать книгу писем» — те же цифры уходят в PDF (см. `docs/diary.md`, раздел «Книга писем»).

Логика: `src/utils/serviceSummary.ts`, хук `src/hooks/useServiceSummaryAutoOpen.ts` (тик раз в секунду + `AppState`).

На главной, если открыта тестовая база, сверху красная полоска. Даты службы, итоги и книга тогда читаются из `zhdi-sandbox.db`, боевой `zhdi.db` не меняется. Переключатель — в настройках дневника, подробно в `docs/diary.md` → «Две базы».

## Срок службы в онбординге

На шаге дат два пикера (`DatePicker`, спиннер). Под ними кнопки:

| Кнопка | Дней | Смысл |
| --- | --- | --- |
| 365 дней | +365 к призыву | год |
| 547 дней | +547 к призыву | полтора года |

Дембель = `addDays(startOfDay(призыв), N)`. Если призыв ещё не выбран, показывается ошибка. Те же кнопки есть в настройках дневника, где правятся даты.

Компонент: `src/components/common/ServiceDurationPresets.tsx`. Константы: `SERVICE_DURATION_PRESETS` в `src/constants/index.ts`.

## Шапка главной

Три зоны в одном ряду (`HomeScreen`):

| Слева | Центр | Справа |
| --- | --- | --- |
| кисть → настройки вида | имя активного таймера + треугольничек | шаринг картинки |
| глаз → показать/скрыть плашки | | сброс данных (иконка refresh) |

Имя стоит **ровно по центру экрана** (абсолютный слой `topBarCenter`). Боковые кнопки фиксированной ширины, чтобы не сдвигать заголовок.

## Несколько таймеров

Основной таймер берёт даты призыва и дембеля. Его **название — имя солдата** из онбординга (`config.partner_name`). Если имени нет, показывается «Служба».

Свои таймеры (учебка, командировка) — JSON `config.custom_timers_data`:

```ts
{ timers: [{ id, name, startDate, endDate }] }
```

Активный id — `active_timer_id` (`service` или uuid).

Нажатие на имя открывает выпадающий список (`TimerSwitcher`):

1. «Добавить таймер» — форма названия и двух дат;
2. основной таймер (имя солдата);
3. остальные сохранённые таймеры.

Тап по строке переключает активный таймер: вместе с плашками «Прошло / Осталось» пересчитываются кольцо или линейная полоса и число в центре. Долгое нажатие на свой таймер открывает правку (название, даты, удаление). Основной таймер из списка не удаляется.

Форма своего таймера: `ExtraTimerFormModal`. Даты — общий `DatePicker`.

## Выбор даты

Общий компонент `src/components/common/DatePicker.tsx`. Используется в онбординге, настройках дневника, форме своего таймера, формах события и праздника.

Поведение:

- кнопка показывает выбранную дату или «Выберите дату»;
- Android — системный календарь через `DateTimePickerAndroid.open` (не виджет внутри `Modal`, иначе диалог сразу закрывается и подставляет сегодня);
- iOS — спиннер в модалке и «Готово»;
- в форму уходит только событие `set` и `startOfDay` выбранного дня.

В шапке дневника тот же системный календарь: `DiaryDateButton`.

## Виджет (Android)

`TimerWidget`: имя активного таймера, число, подпись (ддд / до призыва / после). У основного таймера имя — солдат (`partner_name`). Обновляется из `useServiceTimer` и из `widgetTaskHandler` при добавлении виджета на рабочий стол. iOS-виджета в SDK 51 нет.

Регистрация обработчика — в `index.ts`, только если нативный модуль `AndroidWidget` есть.

Файлы: `src/widgets/*`, `src/utils/timerWidget.tsx`.

## Картинка таймера

Иконка share справа в шапке. На кадр идёт **постер** `TimerShareCard` на весь экран, не скриншот с кнопками: без шапки, списка таймеров, переключателя «прошло / осталось», нижней панели. Вверху постера — имя активного таймера. Фон (градиент или фото) входит в кадр. Пока снимок готовится, на экране виден только этот постер (пауза ~220 мс, с фото ~420 мс).

Снимок: PNG, `quality: 1`, размер `окно × PixelRatio` (`captureRef`).

После снимка диалог:

| Действие | Что делает |
| --- | --- |
| Сохранить в галерею | `MediaLibrary.requestPermissionsAsync(true)` → `saveToLibraryAsync` |
| Поделиться | системный sheet `Sharing.shareAsync` (PNG) |
| Отмена | файл не отправляется |

Плагин `expo-media-library` в `app.json` (доступ на сохранение фото). Файл: `src/utils/shareTimerImage.ts`.

## Нижняя панель и заголовки вкладок

`CustomTabBar` — полупрозрачная белая плашка, как карточки (`rgba(255,255,255,0.48)`), плавает над контентом. На экране таймера с фото заливка пропадает, остаётся тонкая светлая обводка, как у плашек «Прошло / Осталось». Скрывается на `PersonalDiary`, `LetterTheme`, `LetterEditor`, `Settings`.

Заголовки «События», «Трекеры», «Дневник», «Магазин» — `ScreenHeader`: жирный `dmb-timer-sans-Bold`, 24pt, как у дневника.

## Трекеры: название записи

У звонка и встречи поле `title` (опционально). В форме — текстовое поле, в списке дня и карточке детали показывается название, иначе «Звонок n» / «Встреча n». Хранится в JSON трекера вместе с остальными полями записи.

## Архитектура

```
Вкладка Home
 └─ HomeStackNavigator
     ├─ HomeMain            таймер + плашки
     └─ TimerSettings       вид таймера, фото, затемнение
```

Состояние считает `useServiceTimer`:

- читает даты призыва / дембеля и настройки из `config`;
- каждую секунду пересчитывает прогресс;
- `updateSettings` пишет ключи в SQLite и сразу обновляет UI.

Расчёты — `src/utils/timerCalculations.ts`. Типы — `src/types/timer.ts`.

```
HomeScreen
 ├─ ScreenBackground            обычный градиент
 │  или Image + затемняющий слой
 ├─ шапка: кисть / глаз | имя ▾ | шаринг
 ├─ TimerSwitcher               выпадающий список таймеров
 ├─ SegmentedCircularProgress   кольцо
 │  или SegmentedLinearProgress полоса
 │  или FramedTimerDisplay      рамка с ддд/дпп и ближайшим событием
 │  или TimerDotGridDisplay     сетка точек (макет R)
 │  или TimerMilestonesTimelineDisplay  лента вех (макет S)
 ├─ TimerUpcomingCard           карточка ближайшего (кроме вида «Рамка»)
 ├─ TimerStatCard / TimerUnifiedStatCard   одна плашка «прошло | осталось» в active (не для «Рамка»)
 └─ кнопка «Итоги»              после дембеля → ServiceSummaryModal
```

Общий переключатель «прошло / осталось»: `src/components/timer/CenterDisplayToggle.tsx`. Стоит над кольцом, линейной полосой и рамкой (в активной фазе службы). Выбор пишется в `centerDisplay` и переживает перезапуск.

### Отклонённый вариант: переключение по ддд/дпп (✦)

Пробовали режим без кнопок «прошло / осталось»: тап по подписи **ддд/дпп** в центре (в «Рамке» — под числом), маркер **✦** в правом верхнем углу подписи. Настройка в выпадающем списке и ключ `timer_center_display_switch` **убраны из приложения** — UX признан провальным (перегруз, неочевидность). Макеты и обсуждение: `prototypes/timer/stat-labels.html`. **Возможно вернёмся** к идее позже в другом виде; в коде не поддерживается.

## Настройки

Хранятся по отдельным ключам `config`, не одним JSON.

| Ключ | Поле | По умолчанию |
| --- | --- | --- |
| `timer_type` | `circular` / `linear` / `frame` («Рамка») / `dotGrid` («Сетка дней») / `milestones` («Лента событий») | `circular` |
| `timer_milestones_layout` | `spine` / `chips` / `checklist` (только лента событий) | `spine` |
| `timer_upcoming_preview` | карточка на главной: `off` / `nearest` / `pinned` | `nearest` |
| `timer_upcoming_pinned_ref` | `event:id` или `holiday:id` для закрепления | пусто |
| `progress_bar_mode` | `percent` / `weeks` / `months` | `percent` |
| `percent_decimal_places` | `0`–`6` | `2` |
| `timer_center_display` | `remaining` / `elapsed` | `remaining` |
| `stat_card_mode` | `days` / `weeks` / `months` | `days` |
| `timer_background_image` | URI файла или пусто | нет фото |
| `timer_background_dim` | `0`–`100` | `32` |
| `timer_photo_stat_border` | окантовка плашек при фото (`1`/`0`) | `1` |
| `timer_photo_upcoming_border` | окантовка карточки события при фото | `1` |

Старый режим `days` при загрузке сводится к `percent` (`normalizeProgressBarMode`), **кроме** типа «Сетка дней»: там доступны все четыре единицы — дни, проценты, недели, месяцы (настройка «Сетка: единица»).

### Сетка дней и лента вех

Прототипы: `prototypes/timer/variant-r-dot-grid.html`, `variant-s-summary-timeline.html`.

**Сетка дней** — карточка-сводка, поле точек (каждая точка = выбранная единица), легенда, в активной фазе две крупные цифры «прошло / осталось». Отдельная карточка события под таймером как у кольца.

**Лента событий** — сводка как у сетки; ниже хронология событий и праздников из вкладки «События» (в пределах дат таймера). Ближайшее событие — строка в сводке. Вид ленты в настройках: **прямой шток**, **плитки** (горизонтальный скролл), **чеклист**. Ключ `timer_milestones_layout`: `spine` / `chips` / `checklist`.

`percent` на круге в настройках подписан как «Дни»: в центре дни, сверху процент. На линейном тот же режим показывает только проценты.

Знаки после запятой видны в любом режиме, где есть проценты. Если ключа в БД нет — берётся `2`. Уже сохранённое число (в том числе `0`) не перетирается.

URI фото пишется **после** остальных ключей. Так при ошибке записи настроек новый файл можно откатить, не оставляя в БД ссылку на удалённое фото.

## Прошло / осталось и подписи

`centerDisplay` меняет число в центре и подпись под ним.

| Режим | «Осталось» | «Прошло» |
| --- | --- | --- |
| Дни (`percent` на круге) | дни до дембеля + `%` оставшегося, подпись `ддд` | дни после призыва + `%` прошедшего, подпись `дпп` |
| Проценты (линейный) | оставшийся процент | прошедший процент |
| Недели / месяцы | целые оставшиеся единицы | целые прошедшие единицы |

Недели и месяцы склоняются: `41 неделя`, `43 недели`, `45 недель`.

Плашки внизу от этого переключателя не зависят: всегда показывают оба направления. Меняется только их детализация (`stat_card_mode`). В фазах `before` / `after` переключатель скрыт.

## Фото на фоне

Выбор, замена и удаление — на экране настроек таймера.

Поведение:

- фото копируется в `documentDirectory/timer-background/`;
- на главном экране рисуется `resizeMode="cover"` (кадр под экран без искажения);
- поверх — тёмный слой `rgba(8, 8, 10, dim / 100)`;
- текст, иконки и сегменты становятся серовато-белыми (`#F2F0EC`);
- плашки «Прошло / Осталось» и нижняя панель вкладок теряют заливку, остаётся тонкая светлая обводка.

При замене новое фото сначала сохраняется в настройки, старый файл убирается best-effort. Если уборка старого файла упала, новый фон не откатывается.

`resetAllData` читает URI до очистки `config` и удаляет файл фона.

### Затемнение

Ползунок `0`–`80` в настройках, если фото уже выбрано. По умолчанию `32`.

Жест и анимация идут на UI-потоке (`SettingsSlider` + `SharedValue`):

- бегунок и превью не гоняют React-рендер экрана на каждый пиксель;
- в SQLite значение пишется при отпускании пальца;
- вертикальный скролл настроек — `ScrollView` из `react-native-gesture-handler`, чтобы не конфликтовать с горизонтальным жестом.

Компонент: `src/components/common/SettingsSlider.tsx`. Файлы фона: `src/utils/timerBackground.ts`.

## Склонение

Модуль `src/utils/inflection.ts`.

```ts
pluralize(count, one, few, many)   // произвольные формы
inflect(count, 'week')             // готовое слово
formatCount(count, 'week')         // «43 недели»
```

Правило: `11–14` → many; иначе `1` → one, `2–4` → few, остальное → many.

Словарь: день, неделя, месяц, час, минута, секунда, звонок, встреча.

Используется в центре таймера, плашках, событиях, длительностях и статистике трекеров. `src/utils/pluralize.ts` реэкспортирует тот же API.

## Скругления

Декоративные `borderRadius` карт, кнопок, полей и меню уменьшены примерно вдвое (было `12–18`, стало `6–9`).

Круги не трогались: цветовое колесо, маркер на нём, точки календаря, круглый бегунок ползунка.
