# События и праздники

Документация вкладки «События»: служебные события, календарные праздники и их связь с темой письма в дневнике.

## Что использовано

Проект на **Expo SDK 51**. Документация API: https://docs.expo.dev/versions/v51.0.0/

| Задача | API / библиотека |
| --- | --- |
| Хранение списков | `config` в `expo-sqlite` (`EVENTS_DATA`, `HOLIDAYS_DATA` – JSON) |
| UUID пользовательских записей | `expo-crypto` (`randomUUID`) |
| Даты | `date-fns` + `@react-native-community/datetimepicker`, спиннер `DatePicker` |
| Навигация | вкладка `Events` в `MainTabNavigator` |
| Пуши в 00:00 (полночь) | `expo-notifications` ~0.28 (локальный `scheduleNotificationAsync`, DATE trigger) |

Праздничные пуши — только локальные уведомления. Модуль `ExpoPushTokenManager` не загружается: импортируются отдельные файлы `expo-notifications/build/…`. Если нативных модулей планировщика нет, приложение стартует без пушей (`isHolidayNotificationsAvailable`).

## Два типа карточек в одном списке

```
Вкладка Events
 └─ EventsScreen
     ├─ фильтр: Все / События / Праздники, список открывается на ближайшей дате
     ├─ список: события + праздники, сортировка по дате, годы как заголовки
     ├─ «+» → AddKindMenu (событие / праздник)
     ├─ EventFormModal      ддд или календарная дата + иконка
     └─ HolidayFormModal    только календарная дата (день+месяц) + иконка
```

События – вехи ожидания (призыв, месяцы, ддд/дпп, доли срока, экватор, светофор, дембель и пользовательские). Длинный диапазон режется заголовками годов. Вкладка по умолчанию «Все», список сразу прокручивается к ближайшей ещё не прошедшей дате.  
Праздники – даты внутри срока. Один шаблон (день+месяц) разворачивается в отдельную карточку на каждый год от призыва до дембеля: «Новый год 2027», «Зима 2028». Карточка другого цвета. В день праздника письмо открывается с темой «Как я отмечала {название} {год}», для сезонов — «Как я встречала зиму {год}».

## События

Хранение: `config.events_data`.

```ts
{ deletedIds, overrides, customEvents }
```

Предустановленные шаблоны считаются из дат призыва и дембеля (`src/utils/eventCalculations.ts`). Удаление пресета – id в `deletedIds`. Правка пресета – запись в `overrides`. Свои события – `customEvents`.

Автоматические вехи доли срока. На карточке слева дробь — сколько уже прошло, а не сколько осталось:

| Событие | Глиф | Как считается |
| --- | --- | --- |
| Прошла 1/4 службы | `1/4` | четверть срока после призыва |
| Экватор | `1/2` | середина срока |
| Прошло 3/4 службы | `3/4` | четверть срока до дембеля |
| Прошла 1/3 службы | `1/3` | треть срока после призыва |
| Прошло 2/3 службы | `2/3` | треть срока до дембеля |

Месяцы службы и вехи 100/200/300 ддд и дпп больше не показывают `1/12` или число: у них общая иконка-звезда. Это не привязано к годичному сроку и одинаково читается на контракте и на четырёх годах ожидания.

Свои события и праздники получают иконку из каталога (`EVENT_ICON_CATALOG` в `src/utils/eventGlyphs.ts`): прежние глифы плюс дни рождения, письма, встречи, дом. У пресета можно вернуть автоматический глиф пунктом «Авто». Поле `icon` лежит в `customEvents` / `customHolidays` и в `overrides`.

Форматы даты события:

- `ddd` – дней до дембеля
- `dpp` – дней после призыва
- `date` – конкретный календарный день

Без дат призыва/дембеля список событий пуст. Праздники тогда показываются одной карточкой на текущий календарный год.

## Праздники

Хранение: `config.holidays_data`. Та же схема, что у событий:

```ts
{ deletedIds, overrides, customHolidays: [{ id, name, month, day, icon }] }
```

`month`/`day` – 1-based. Год в форме не хранится: при показе шаблон разворачивается на все годы службы. 29 февраля в невисокосный год показывается и срабатывает как 28 февраля.

### Предустановленные

| Дата | Название | Иконка |
| --- | --- | --- |
| 1 января | Новый год | ёлка |
| 14 февраля | День святого Валентина | поцелуй |
| 23 февраля | 23 февраля | щит со звездой |
| 1 марта | Весна | росток |
| 8 марта | 8 марта | тюльпан |
| 9 мая | День Победы | медаль |
| 1 июня | Лето | солнце |
| 8 июля | День семьи, любви и верности | кольцо |
| 1 сентября | Осень | лист |
| 1 декабря | Зима | снежинка |

Рождество, Старый Новый год, Крещение и 1 сентября убраны из пресетов. Старые письма с темой `holiday:predefined-holiday-…` всё ещё показывают прежнее название (`LEGACY_HOLIDAY_NAMES`).

Пользовательские – кнопка «+» → «Праздник»: название, иконка и дата. Годовщина, дни рождения и любые свои дни добавляются так.

Изменение и удаление как у событий: карандаш / крестик, снекбар «Отменить удаление» 5 с. Пресет при удалении скрывается через `deletedIds` и возвращается после сброса данных. Свой праздник удаляется из массива.

Цвет карточки: `colors.light.holiday` (пыльная коралловая заливка и рамка), события остаются бежево-белыми.

## Тема письма в день праздника

Каталог тем (`letter_themes`, около 800 сидов плюс свои `custom-*`) по-прежнему случайный. Исключение – день, у которого есть праздник.

1. `useLetterThemes(date)` подмешивает виртуальные темы `holiday:{holidayId}:{year}`.
2. Заголовок: `Как я отмечала {название} {год}` (год берётся из даты письма, не из формы праздника).
3. Первый показ экрана темы выбирает праздничную тему (`pickPreferredTheme`). Shuffle может взять другую свободную тему из каталога; праздничную можно вытянуть снова, пока письмо за этот день не сохранено.
4. Если на дату несколько праздников, первыми идут пользовательские, затем пресеты.
5. Виртуальные id в таблицу `letter_themes` не пишутся. После сохранения `theme_id` лежит в `diary_entries`, как у обычных тем.
6. Если праздник потом удалили, заголовок старого письма восстанавливается из id, из `LEGACY_HOLIDAY_NAMES` или становится «Как я отмечала этот день {год}».

`resetAllData` чистит `config` целиком: пользовательские праздники пропадают, пресеты праздников снова на месте.

## Потоки экранов

### Добавить праздник

Вкладка События → «+» → Праздник → название + иконка + дата → Готово. В списке появляются коралловые карточки на каждый год срока, например «Новый год 2027». Под датой: «До даты n дней». Прошедшие карточки полупрозрачные, сегодняшняя — с более тёмной рамкой.

### Письмо 1 января

Дневник → письма → если на 1 января ещё нет записи → «Твоя тема на сегодня:» «Как я отмечала Новый год 2026» (год как у выбранной даты).

## Решения, которые сознательно приняты

1. **JSON в `config`, не отдельная SQL-таблица.** Совпадает с событиями; пресеты можно пересчитать без миграции столбцов.
2. **Только день и месяц в хранении.** Иначе Новый год 2025 и 2026 пришлось бы заводить дважды. На экране шаблон разворачивается на годы службы; год в теме письма берётся из даты дневника.
3. **Список праздников зависит от дат службы.** Без призыва/дембеля остаётся одна карточка на текущий календарный год.
4. **Праздничная тема не вытесняет каталог насовсем.** В этот день она первая, но shuffle остаётся.
5. **Под датой нет ддд/дпп.** И у событий, и у праздников подпись «До даты n дней» (для сегодня — «Сегодня»).
6. **Дроби на карточке — прогресс, не остаток.** `3/4` и `2/3` вместо «осталась 1/4 / 1/3», чтобы год и четыре года читались одинаково.
7. **Звезда вместо `1/12` и чисел 100/200/300.** Эти подписи выглядели как «служба ровно год».
8. **Список открывается на ближайшей дате.** Фильтр по умолчанию «Все», прошедшее остаётся сверху, но сразу видна следующая веха.
9. **Сезоны — праздники.** Весна / лето / осень / зима повторяются каждый год и пишутся как «Зима 2026». Это не разовые события службы.

## Выбор даты праздника и события

Формы `HolidayFormModal` и `EventFormModal` (режим календарной даты) используют общий `DatePicker`: системный календарь Android / спиннер iOS. Подробности — в `docs/timer.md`, раздел «Выбор даты».

## Уведомления о праздниках

Локальные пуши `expo-notifications` ~0.28. На каждый будущий экземпляр праздника в диапазоне службы ставится уведомление **в 00:00** этого дня (`trigger: { date, channelId: 'holidays' }`). Заголовок — название праздника, текст «Сегодня {название}».

Список пересобирается:

- загрузка и CRUD праздников (`useHolidays`);
- сохранение дат службы (`useProfile`, онбординг);
- старт приложения, если онбординг уже пройден.

Старые уведомления с id `holiday:…` снимаются перед новой записью. Разрешение запрашивается при первом планировании. Канал Android: «Праздники», importance HIGH. Плагин в `app.json`: иконка, цвет `#3E3630`, канал `holidays`.

`setNotificationHandler` вызывается при первой успешной загрузке нативных модулей (`ExpoNotificationsHandlerModule`, `ExpoNotificationScheduler`, `ExpoNotificationPermissionsModule`, на Android ещё `ExpoNotificationChannelManager`).

Файл: `src/services/holidayNotifications.ts`.
