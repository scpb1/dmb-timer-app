# Как запустить бота на этом компьютере

Нужен Node.js. На этой машине он уже стоит (v24). Окно, в котором запущен бот, не закрывай: пока оно открыто, бот отвечает. Второе окно с ботом не запускай, иначе два процесса начнут мешать друг другу.

## 1. Токен

1. В Telegram открой [@BotFather](https://t.me/BotFather).
2. Если бота ещё нет: `/newbot`, имя и username. Если бот уже есть: `/token` и выбери его.
3. Скопируй токен.
4. В папке `bot` уже есть файл `.env`. Открой его блокнотом и проверь строку:

```
BOT_TOKEN=токен_от_BotFather
```

Не выкладывай этот файл и не присылай токен в чат. Канал по умолчанию `girly_ddd`, отзывы уходят на `imklvcva`.

## 2. Бот — админ канала

Проверка подписки работает, только если бот добавлен в канал «Девичья служба» администратором. Иначе бот ответит, что не может проверить подписку.

Со своего аккаунта админа один раз напиши боту `/start` в личке. Пока этого не было, отзывы копятся и придут, когда админ откроет бота.

## 3. Запуск

PowerShell:

```powershell
cd C:\Users\anwxcr\source\repos\dmb-timer-app\bot
npm install
npm run dev
```

В консоли должно появиться `Бот запущен как @...`. Остановка: `Ctrl+C` в этом окне.

`npm run dev` перезапускает бота, когда меняются файлы. Для обычного запуска без слежки за файлами: `npm start`.

Часовой пояс в `.env` — `Europe/Moscow`. Дни считаются по московской дате, даже если Windows думает иначе.

## 4. Проверка в личке

1. Найди бота в Telegram и нажми `/start`.
2. Подпишись на канал и нажми «Проверить подписку».
3. «Срок службы» — дата призыва `ДД.ММ.ГГГГ`, потом дата дембеля или кнопка 365 / 547.
4. «События»: призыв, дембель и события срока уже стоят. «Посмотреть другие события» добавляет армейские из списка. «Добавить событие» создает свое: название и датой строкой ниже.
5. «Написать автору» — 👍🏻 Зашло, 👎🏻 Бесит, 🐞 Баг или 💡 Идея. Текст придёт админу.

Чтобы увидеть разные сроки, в «Настройках» поставь другие даты:

- призыв в будущем — «Служба скоро», «до призыва осталось»;
- призыв сегодня — «сегодня призыв»;
- дембель завтра — «завтра дембель»;
- дембель сегодня — «сегодня дембель»;
- дембель в прошлом — «Служба завершена!», «прошло с дембеля».

## 5. Проверка в беседе

1. Создай группу и добавь туда бота. Он напишет, что делать. Бот должен видеть обычные сообщения: сделай его администратором или в BotFather выключи Privacy mode (`/setprivacy` → Disable). Иначе «Таймер» и «Сводка» до него не дойдут.
2. Каждый, кто должен быть в сводке, сначала пишет боту в личку `/start`, ставит даты и подписывается. Потом в группе пишет «Новый таймер» или `/newdmb`. Без лички бот человека не знает. «Таймер» и `/mydmb` только показывают срок, в сводку не добавляют.
3. «Таймер» отвечает на это сообщение. «Таймер @имя» показывает срок другого человека, только если он уже включил таймер в этой беседе, всё ещё в ней состоит и вообще пользуется ботом.
4. «Сводка» или `/list_dmb` сразу пишет ближайшие дембеля. События на сегодня — «События» или `/list_events`. Ждать 10:00 не нужно. Ответ приходит на сообщение, которым позвали команду.
5. Событие пишется только тем, у кого оно сегодня. Экватор, призыв и дембель стоят сами. Новый год, весна и лето больше не пишутся.
6. Настройки автосводки и часов — `/lists_settings` (только админ). Кнопки интервала, отдельно час сводки дембелей и час событий за сегодня. Свой промежуток: `/lists_settings 10`, раз в 10 дней, от 1 до 365.
7. По умолчанию сводка и события уходят с 10:00 по Москве (часы можно развести). Если компьютер в это время спал, бот отправит их, когда его включат после заданного часа. «Сводка» и `/list_dmb` показывают список сразу.

## Деплой на сервер одной командой

В корне репозитория (не в `bot/`):

1. Скопируй `.bot-deploy.env.example` → `.bot-deploy.env`, впиши IP и пользователя `deploy`.
2. В **Git Bash** из корня проекта:

```bash
chmod +x bot-deploy.sh
./bot-deploy.sh          # залить bot/ с этого ПК (можно без коммита в GitHub)
./bot-deploy.sh git      # сначала push в GitHub, потом pull на сервере
./bot-deploy.sh git --no-push   # только обновить сервер с уже запушенного main
```

На сервере не перезаписываются `.env` и папка `data/` (база пользователей бота). После заливки выполняется `npm ci` и `systemctl --user restart girly-ddd-bot`.

Первый раз на сервере всё равно нужны `.env` и systemd (см. инструкцию в чате / WinSCP). Режим `git` при первом запуске сам клонирует репозиторий в `BOT_REPO_DIR` и копирует только `bot/` в `BOT_DEPLOY_PATH`.

SSH по ключу ускорит деплой (без ввода пароля каждый раз). Пароль по-прежнему подойдёт, Git Bash спросит его при `ssh`.

### Только PuTTY (как другой проект на сервере)

См. **`bot/DEPLOY-PUTTY.md`**. Кратко: push с ПК → в PuTTY одна команда:

```bash
bash ~/girly-ddd-bot/scripts/server-update.sh
```

Без Git Bash на Windows. WinSCP + `server-update.sh reload`, если заливаешь файлы руками.
